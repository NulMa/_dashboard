# Ghost_March — 모바일 런타임 폴리싱 스냅샷

## 1. 주요 변경사항
- Android release version name/code를 `3.0.3` / `67`로 고정하고, HUD에 Android `versionCode`를 표시하는 경로를 추가했다.
- 레벨업 선택 화면에 터치 릴리즈 가드와 후보 가중치를 넣어 모바일 오입력과 성장 체감을 개선했다.
- EXP 바, damage digit, 적 outline, 특수기 HUD 파티클 등 모바일 시인성 중심의 렌더링 튜닝이 들어갔다.
- `live_data_default.json`과 generated 데이터에서 경험치 요구량, 몬스터 속도·체력, spriteType이 대규모로 조정됐다.
- 각성 부적 쿨다운이 glove/live_data/minCooldown 영향을 받도록 수정되어 실제 성장 수치와의 연결이 좋아졌다.

## 2. 코드 품질 리뷰
이번 변경의 강점은 모바일 런타임에서 실제로 불편했던 지점을 직접 겨냥했다는 점이다. `LevelUpScreen`의 입력 가드는 터치가 누른 상태로 카드가 열리자마자 선택되는 문제를 구조적으로 막는다. `VerticalSliceInputBridge.CancelTouchUntilRelease()`와 연결한 판단도 좋다. 다만 `FindFirstObjectByType<VerticalSliceInputBridge>()`가 화면 코드에 들어간 것은 장기적으로 UI가 씬 검색에 의존하게 만드는 신호다. 지금은 허용 가능하지만, UIManager 또는 bootstrap 주입 경로로 정리하는 편이 테스트와 씬 재구성에 강하다.

자료구조/복잡도 관점에서는 `LevelUpScreen.BuildCandidates()`가 `NativeList<int>`에서 `List<WeightedCandidate>`로 바뀌었고, 후보 수가 아이템 타입 수로 제한되어 비용은 작다. `TakeWeightedCandidate()`의 `RemoveAt(i)`는 O(n)이지만 최대 3회 추출이라 현재 구조에서는 문제가 아니다. 반면 `HUDScreen.CreateExpBarTexture()`는 layout 크기 변경 때마다 전체 픽셀 배열을 새로 만들고 `Texture2D`를 생성한다. 매 프레임 경로는 아니지만, 모바일에서 sprite import의 Read/Write 설정이 꺼져 있으면 `GetPixels32()`가 실패하고 EXP 바가 조용히 빠질 수 있다. 이 부분은 import 설정 검증 또는 원본 sprite 반복 렌더링 fallback이 필요하다.

렌더링 브리지는 body emission, 타입별 enemy pass, shader tile clamp를 추가해 시인성 문제를 적극적으로 해결했다. 다만 적 렌더링이 visualType 5종 × elite 2종으로 pass를 늘렸기 때문에 draw call과 CPU loop 비용이 증가한다. 1500 적 기준 실기 프레임 재측정 없이 이 변경을 완료로 간주하면 위험하다.

## 3. 진행도 평가
네트워킹 코드는 없는 단일 플레이 수직 슬라이스 경로로 판단한다. 고수준 네트워크 구현 부담은 없고, 대신 모바일 빌드 안정성·씬 흐름·입력 UX·밸런스 완성도가 핵심 기준이다. 이번 범위는 release AAB 메타데이터, HUD 버전 표시, 모바일 터치 오입력, 전투 시인성, 성장 수치까지 이어져 제출 가능한 빌드 쪽으로 분명히 전진했다.

진행도는 78%로 본다. 반복 플레이 가능한 vertical slice는 상당히 갖춰졌으나, Android 실기 smoke와 대량 적 성능 재측정, PostProcessTuning 씬 생성화가 아직 막판 리스크다. 위험도는 high까지는 아니지만, 실기 검증 없이 폴리싱 변경을 누적하면 발표 직전 회귀가 발생할 수 있어 medium이 적절하다.

## 4. 다음 권장사항
- `0086.aab` 기준으로 MainMenu 진입, 캐릭터 선택, DotsVerticalSlice 플레이, 일시정지/레벨업/결과 흐름을 Android 실기에서 반복 smoke로 고정한다.
- `PostProcessTuning.unity`는 리뷰 가능한 생성 스크립트 중심으로 줄이고, 씬 YAML을 사람이 직접 관리하는 범위를 최소화한다.
- EXP 바 런타임 텍스처 생성은 Android import 설정과 실패 fallback을 확인한다. 실패 시 경고만 남기면 실제 UI 결함을 놓친다.
- damage digit, 특수기 파티클, enemy glow 변경은 1500 적 부하와 함께 실기 프레임·가독성 기준으로 재측정한다.
- Hard mode와 live_data override 적용 순서는 테스트로 고정한다. 밸런스 수치가 많이 바뀐 만큼 회귀 비용이 크다.

## 5. 문서화 상태
design은 8점이다. `docs/planning/game-design-spec.md`, `ui-plan.md`, `singleplayer-ui-completion-plan.md`가 게임 루프와 UI 흐름을 충분히 설명한다. 다만 일부 unlock·밸런스 규칙은 아직 코드와 문서가 완전히 한 곳으로 모이지 않았다.

technical은 9점이다. assembly boundary, UI Toolkit 구조, live-data patch boundary, Android release build 문서가 실무 인수인계에 충분한 수준이다. 이번 release versioning과 AAB 검증 기록도 운영 문서에 잘 반영됐다.

spec은 8점이다. live data, mob/progression CSV, validation checklist, unlock-save contract 문서가 테스트 기준으로 활용 가능하다. 다만 최근 밸런스 대규모 변경에 대해 “왜 이 수치인가”와 실기 결과가 아직 문서에 충분히 연결되지는 않았다.
