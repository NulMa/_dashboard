# Ghost_March — UI 전환 안정화 스냅샷

## 1. 주요 변경사항
- Pause, Bestiary, WeaponInfo, EvoSelect, Achievement, AppExitDialog, CommandInput smoke가 추가되며 UI Toolkit 전환 검증 범위가 크게 넓어졌다.
- LevelUp, ItemSelection, MainMenu smoke에서 private reflection 의존을 제거하고 공개 테스트용 API로 접근한 점은 좋은 개선이다.
- `VerticalSliceSpritePresentation`을 제거하고 GPU 렌더 브리지와 digit shader/material 경로로 정리해 표현 계층이 단순해졌다.
- 힐 소울, 아이템 선택 SFX, 콤보 SFX, 업적 기록 등 레거시 패리티 갭을 실제 코드로 줄였다.
- `GetSingletonRW` 반복 호출, `ToEntityArray` 기반 파괴, 중복 무기 기본값 생성이 정리되어 DOTS 코드 품질이 개선됐다.

## 2. 코드 품질 리뷰
이번 변경의 강점은 “검증 가능한 전진”이다. UI 화면을 추가한 것에서 멈추지 않고 smoke runner를 화면별로 붙였고, `PauseUiSmokeTestRunner`가 `Time.timeScale`과 pause token까지 확인하는 점은 단순 표시 검증보다 한 단계 낫다. `BaseScreen.SafeDisposeQuery` 위임, `VerticalSliceItemDefinitions.Default*()` 중앙화, `UIManagerPresence`로 assembly 순환을 끊은 선택도 방향이 맞다.

다만 `UIManagerPresence.IsActive`와 `RunSessionConfig`는 모두 static 상태다. 왜 문제냐면 Enter Play Mode 옵션, 씬 재로드, 테스트 연속 실행에서 상태가 실제 씬 생명주기와 어긋날 수 있기 때문이다. `UIManagerPresence`는 순환 의존성 제거용 얇은 플래그라 단기적으로 수용 가능하지만, `RunSessionConfig`는 캐릭터·로비·재시작 흐름이 붙기 전에 ScriptableObject 런 세션 또는 scene bootstrap 인스턴스 상태로 옮기는 편이 좋다.

자료구조/복잡도/할당 관점에서는 명확한 개선이 있다. `GameRestartSystem.DestroyAllWith`가 `ToEntityArray(Allocator.Temp)` 후 파괴하던 흐름을 query 직접 파괴로 바꿔 임시 NativeArray 할당을 제거했고, 여러 시스템에서 singleton stats 쓰기를 루프 밖으로 모았다. 현재 구조의 비용은 hot path에서 반복 lookup/write와 임시 배열이 생기는 것이었고, 이번 대안은 query/singleton 접근을 한 번으로 고정한다. DOTS 수직 슬라이스처럼 적·투사체 수가 늘어나는 프로젝트에서는 이런 작은 할당 제거가 프레임 안정성에 직접 의미가 있다.

## 3. 진행도 평가
네트워킹 구현은 현재 코드 범위에서 실질적으로 해당 없음이다. 따라서 진행도는 고수준 네트워크 경로 보정 없이, 단일 플레이 DOTS 수직 슬라이스 기준으로 본다. 핵심 전투 루프, UI 전환, 레거시 패리티, smoke 검증이 묶여 있어 제출 가능한 수직 슬라이스는 70%대 중반까지 올라왔다.

위험도는 low가 아니라 medium이다. 이유는 기능 자체보다 마감 직전 수동 의존이 남아 있기 때문이다. Inspector SFX/material 할당, 모바일 실기 시각 검증, Burst 내부 버그로 제외된 시스템, static 세션 상태가 아직 남아 있다. 지금 1일 정도 정리하면 이후 2주 디버깅 비용을 줄일 수 있는 전형적인 단계다.

## 4. 다음 권장사항
- `DotsVerticalSlice.unity`에서 `sfxClips[10~12]`와 `healSoulMaterial`을 실제 에셋으로 고정하라.
- damage digit, hit flash, special effect 크기와 알파를 모바일 해상도에서 직접 확인하라.
- `EnemySeparationSystem` 최적화 이후 목표 단말 프레임을 다시 측정하고 문서 수치를 갱신하라.
- Burst 제외 4개 시스템은 Unity/Burst 업그레이드 후 같은 smoke 기준으로 재시도하라.

## 5. 문서화 상태
design은 8점이다. `docs/planning/game-design-spec.md`와 `docs/planning/ui-plan.md`가 코어 루프, UI 흐름, 화면 목록을 충분히 담고 있다. 다만 unlock·업적 같은 일부 규칙이 코드 상수와 문서 설명에 나뉘어 있어 단일 기준 문서로는 아직 약하다.

technical은 9점이다. assembly boundary, folder/asmdef layout, live data patch boundary, GPU presentation troubleshooting, handoff-state가 신규 참여자가 구조를 따라갈 수 있을 정도로 촘촘하다. 이번 handoff 갱신도 실제 검증 로그를 남겨 추적성이 좋다.

spec은 8점이다. 기능 목록, UI 화면, 수직 슬라이스 검증 루프, 레거시 기준 문서가 테스트 체크리스트로 활용 가능한 수준이다. 다만 최종 밸런스 수치와 에셋 Inspector 할당 상태는 문서보다 씬 상태에 더 의존한다.

## 6. Backlog
- `RunSessionConfig가 임시 static 세션 상태로 남아 있음`: 현재도 `RunSessionConfig`가 static class로 남아 있다. 지금은 캐릭터 선택 정도라 버티지만, 로비·재시작·저장 상태가 붙으면 씬 생명주기와 분리되어 재현 어려운 버그를 만든다.
- `도감·업적 unlock 규칙이 코드 상수와 문서 트레이드오프에 분산됨`: `BestiaryScreen`의 `unlockKills`와 문서의 UI 계획이 분리되어 있다. 밸런스 패치와 세이브 검증을 안정화하려면 unlock 규칙을 데이터 테이블 또는 ScriptableObject 기준으로 모아야 한다.
